# 部署到阿里云服务器（1.6G 内存版）

> 面向内存紧张的机器。本文所有内存数字都是**实测值**，不是估算。

## 〇、先算内存账

| 项目 | 内存 |
| --- | --- |
| 服务器总内存 | 1600 MB |
| 已经被占用 | 1000 MB |
| **当前可用** | **约 600 MB** |

要往这 600 MB 里塞：

| 要跑的东西 | 实测占用 |
| --- | --- |
| Java 后端（默认 profile） | **335 MB** |
| Java 后端（sharding profile） | 433 MB |
| Redis | ~15 MB |
| **合计（用默认 profile）** | **~350 MB** |

剩约 250 MB 余量。**能跑，但没有余量**，所以下面两件事是必须做的，不是可选优化：

1. **加 swap** —— 否则内存一旦抖动，Linux 的 OOM Killer 会直接把 Java 进程杀掉（表现为「服务莫名其妙挂了」）
2. **限制 JVM 堆** —— JVM 默认最大堆是物理内存的 1/4，在这台机器上是 400 MB，加上元空间、线程栈、直接内存，RSS 会冲到 600 MB 以上，必被 OOM

另外：**服务器上用默认 profile，别用 sharding**，省 100 MB。分库分表在你本机演示就够了，面试时讲清楚原理即可。

## 一、登上去先看内存去哪了

```bash
ssh root@你的公网IP

free -h                          # 看总内存 / 已用 / swap
ps aux --sort=-%mem | head -15   # 看谁在吃内存
df -h                            # 看磁盘剩余（等下要建 swap 文件）
```

> **重要：别只看宝塔面板的数字。** 宝塔首页的「已用内存」把 `buff/cache`（文件缓存）也算进去了，
> 而缓存是程序要用时立刻就能回收的。**以 `free -h` 的 `available` 列为准**，那才是真正能用的。

重点看有没有 **宝塔面板**（`/www/server/panel`，Python 进程，通常吃 150~300 MB）。如果你只是想跑项目、暂时不用面板，可以停掉它：

```bash
bt stop          # 宝塔自带命令
# 或者： /etc/init.d/bt stop
```

这一步能直接腾出几百兆，比什么优化都管用。

### 1.1 顺手要回 192 MB（2G 机器专属）

「买的 2G，`free -h` 只看到 1.6G」是正常现象，不是被坑：

```
2048 MiB   购买标称的 2 GiB
 -192 MiB  crashkernel 预留(Kdump 内核崩溃转储用) ← 可以释放
 -160 MiB  内核自身 + 页表 + 硬件/虚拟化保留      ← 不可避免
─────────
≈1696 MiB ≈ 1.66 GiB
```

阿里云默认配置是 `crashkernel=0M-2G:0M,2G-8G:192M,8G-128G:256M,128G-:384M`，
`2 GiB = 2.147 GB` 刚好越过 2 GB 这条线，所以落进了「预留 192 MB」那一档。

先确认它真的占了：

```bash
cat /proc/cmdline                  # 有没有 crashkernel= 字样
cat /sys/kernel/kexec_crash_size   # 单位字节, 201326592 = 192MB
```

释放（**代价：内核崩溃时收不到转储信息，学生项目无所谓**）：

```bash
# CentOS / Alibaba Cloud Linux 3
sudo cp /usr/share/alinux-base-setup/cmdline /usr/share/alinux-base-setup/cmdline.bak
sudo vim /usr/share/alinux-base-setup/cmdline     # 删掉 crashkernel=... 那一段
sudo grub2-mkconfig -o /boot/grub2/grub.cfg

# Alibaba Cloud Linux 2 / CentOS
sudo cp /etc/default/grub /etc/default/grub.bak
sudo vim /etc/default/grub                         # 在 GRUB_CMDLINE_LINUX 里删掉 crashkernel=...
sudo grub2-mkconfig -o /boot/grub2/grub.cfg

# Ubuntu / Debian
sudo cp /etc/default/grub /etc/default/grub.bak
sudo vim /etc/default/grub
sudo update-grub

# 关闭 kdump 后重启
sudo systemctl disable kdump && sudo systemctl stop kdump    # Ubuntu 上是 kdump-tools
sudo reboot
```

重启后验证：

```bash
cat /sys/kernel/kexec_crash_size   # 应该变成 0
free -h                            # total 会涨到约 1.85G
```

> ⚠️ 改 grub 前务必备份（上面命令已带 `.bak`）。改错会导致系统起不来，只能走阿里云控制台的 VNC 救援。

## 二、加 swap（必做）

```bash
# 建一个 2G 的 swap 文件
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile

# 开机自动挂载
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

# 降低换出倾向: 尽量先用物理内存, 真不够了才用 swap
echo 'vm.swappiness=10' | sudo tee -a /etc/sysctl.conf
sudo sysctl -p

free -h          # 确认 Swap 那行有 2.0Gi
```

> swap 是「保险丝」不是「扩容」。它防止进程被杀，但用多了会变慢。真正的解法是限制 JVM 堆（下一步）。

## 三、装运行环境

服务器上**只装运行时，不装 Maven**。原因：`mvn package` 要下载几百兆依赖 + 编译，小内存机器大概率直接卡死。**在你自己电脑上打好 jar，上传上去就行。**

### 3.1 先确认系统版本和包名（重要）

不同 Ubuntu 版本的包名不一样，**别照抄 JDK 版本号**：

```bash
cat /etc/os-release | head -2      # 确认是哪个版本

sudo apt update
apt-cache search openjdk | grep -i jre-headless    # 看这个版本有哪些 JDK 可装
apt-cache policy redis-server                       # 确认 redis 可装(26.04 是 8.0.x)
```

> **Ubuntu 22.04**：`openjdk-17-jre-headless` / `openjdk-21-jre-headless`
> **Ubuntu 24.04**：`openjdk-21-jre-headless`
> **Ubuntu 26.04**：默认是 **OpenJDK 25**，老的 17 可能已从源里移除
>
> 本项目编译目标是 Java 8 字节码，**上面任何一个都能跑**，装 search 出来的那个就行。

如果 `apt-cache policy redis-server` 显示 `Candidate: (none)`，说明 **universe 仓库没启用**：

```bash
sudo apt install -y software-properties-common
sudo add-apt-repository universe && sudo apt update
```

### 3.2 安装

```bash
# JDK: 只要运行时。headless 版比完整 JDK 省几十兆内存
sudo apt install -y openjdk-21-jre-headless      # ← 换成上一步查到的实际包名

# MySQL 和 Redis
sudo apt install -y mysql-server redis-server

java -version    # 确认装好
```

启动并设为开机自启：

```bash
sudo systemctl enable --now mysql redis-server

# 两个都应该是 active (running)
systemctl status mysql redis-server --no-pager

# 顺手验证 Redis 通不通
redis-cli ping        # 期望输出 PONG
```

## 五、MySQL 调优（省内存的关键）

MySQL 8 默认配置在这台机器上很吃内存，改一下：

```bash
sudo nano /etc/mysql/mysql.conf.d/mysqld.cnf
```

在 `[mysqld]` 段下加：

```ini
innodb_buffer_pool_size = 64M
performance_schema = OFF
max_connections = 50
table_open_cache = 64
```

> `performance_schema = OFF` 单独就能省 100~200 MB，学生项目根本用不到性能监控表。

```bash
sudo systemctl restart mysql
free -h    # 看看是不是又腾出来一块
```

## 七、用 systemd 常驻运行（带 JVM 内存限制）

直接 `nohup java -jar` 也能跑，但**进程挂了不会自动重启**，而且容易被 OOM 杀掉。用 systemd：

```bash
sudo nano /etc/systemd/system/campus-trading.service
```

写入：

```ini
[Unit]
Description=Campus Trading Backend
After=network.target mysql.service redis-server.service
Wants=mysql.service redis-server.service

[Service]
Type=simple
WorkingDirectory=/opt/campus-trading

# 数据库账号密码(不要写死在 jar 里, 用环境变量注入)
# 对应 application.yml 里的 ${DB_USERNAME:root} / ${DB_PASSWORD:123456}
Environment="DB_USERNAME=campus"
Environment="DB_PASSWORD=换成你在第四步设的密码"
# Redis 不在本机时改这两个
#Environment="REDIS_HOST=localhost"
#Environment="REDIS_PORT=6379"

# 关键: 显式限制内存, 防止把服务器撑爆
#   内存 >= 4G: 可以用 -Xms512m -Xmx768m, 下面这些限制没必要卡这么死
#   内存 2G 左右: 保持下面的配置
#   -Xmx320m          最大堆 320M(实测 335M RSS 够用)
#   -Xss512k          线程栈减半, 84 个线程能省 ~40M
#   MaxMetaspaceSize  元空间上限, 防止类加载无限增长
#   UseSerialGC       小内存/单核机器上比 G1 更省 CPU 和内存
ExecStart=/usr/bin/java \
  -Xms192m -Xmx320m \
  -XX:MaxMetaspaceSize=160m \
  -XX:MaxDirectMemorySize=64m \
  -Xss512k \
  -XX:+UseSerialGC \
  -XX:+HeapDumpOnOutOfMemoryError \
  -XX:HeapDumpPath=/opt/campus-trading/logs \
  -jar /opt/campus-trading/campus-trading-backend-1.0.0.jar

SuccessExitStatus=143
Restart=always
RestartSec=10

StandardOutput=append:/opt/campus-trading/logs/app.log
StandardError=append:/opt/campus-trading/logs/err.log

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now campus-trading

# 看状态和日志
sudo systemctl status campus-trading
tail -f /opt/campus-trading/logs/app.log
```

看到 `Started CampusTradingApplication` 就成功了。

## 八、放行安全组（最容易漏的一步）

**阿里云控制台 → 云服务器 ECS → 安全组 → 配置规则 → 入方向 → 手动添加**：

| 协议 | 端口 | 授权对象 |
| --- | --- | --- |
| TCP | 8080 | 0.0.0.0/0 |

> 云服务器默认只开 22。**安全组不放行，本机 curl 通、外面就是连不上**，很多人卡在这里几小时。

Linux 自身的防火墙如果开着也要放行：

```bash
sudo ufw allow 8080/tcp        # 如果启用了 ufw
# 或者: sudo iptables -I INPUT -p tcp --dport 8080 -j ACCEPT
```

## 常见问题

**Q: 服务跑一会儿就没了，日志也没报错？**
被 OOM Killer 杀了。`dmesg | grep -i "killed process"` 确认。解决：确认 swap 生效、确认 `-Xmx` 参数生效、停掉宝塔。

**Q: 上传的图片重启后 404？**
`application.yml` 里 `upload.dir: ./uploads` 是相对路径，相对的是 systemd 的 `WorkingDirectory`。上面配的是 `/opt/campus-trading`，所以图片存在 `/opt/campus-trading/uploads`。**只要别改 WorkingDirectory，图片就不会丢。**

**Q: 想换端口？**
改 `application.yml` 的 `server.port`，同时安全组要放行新端口。

**Q: 想用域名？**
国内服务器**必须先 ICP 备案**，否则 80/443 会被运营商拦截。备案走阿里云控制台，一般 7~20 天。不想备案就继续用 `IP:8080`。

**Q: 前端页面刷新 404？**
Vue Router 的 history 模式问题，见 README / 部署说明里的 `SpaForwardConfig`。或者把前端路由改成 hash 模式。

**Q: Redis 要不要装？**
要。服务器上 `redis-server` 已经在第三步装了，默认监听 127.0.0.1:6379、无密码，和 `application.yml` 的配置一致，**不用改任何配置**。注意本机那个 Windows 绿色版 Redis 拷过来不能用，Linux 上要重新装。
